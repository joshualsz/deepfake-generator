## 1. Remove the repo-fixer replay eval (11:10)

**Files:** `scripts/eval_repo_fixer.py`, `evals/repo_fixer/` (5 cases + 1 saved result), `evals/README.md`, `scripts/eval_rules.py`, `scripts/eod_capture_hook.py`
**Context:** Agent evals added on 2026-10-14. Edits were made via `git rm` and a Python script, so the capture hook did not see them.

### Before
Two evals existed. The rules eval was free; the repo-fixer replay eval ran a headless `claude -p --agent repo-fixer` per trial. `eval_rules.py` and `eod_capture_hook.py` both had an early return when `DEEPFAKE_EVAL_RUN` was set.

### Problem
The replay eval costs API money (the one run recorded about $0.13 per trial; heavy cases would cost more), and the user did not want a paid eval in the project.

### Solution
Deleted the runner script and the whole `evals/repo_fixer/` folder, cut the replay section and table row from `evals/README.md`, and removed the `DEEPFAKE_EVAL_RUN` early returns, which only the replay eval ever set.

### Result
`python scripts/eval_rules.py --selftest` reports 37/37 pass. Committed and pushed as "Remove repo-fixer replay eval (costs API money); keep rules eval". Old 2026-10-14 EOD entries still describe the replay eval as a historical record.

## 2. Helper script to merge stashed trace-log lines (11:15)

**Files:** scratchpad `merge_log.py` (outside the repo)
**Context:** Removing the `Co-Authored-By: Claude` trailer from the initial commit via `git filter-branch`, run by the user in their own terminal.

### Before
Did not exist.

### Problem
`logs/agent_events.jsonl` is tracked and the trace hook appends to it constantly. Two `git stash` runs each saved different appended lines. Popping both conflicted because both stashes touch the end of the same file.

### Solution
A small script that takes the file as stashed (base + earlier lines), appends the later lines from the working tree, and rewrites the log in order. The user runs it, then `git stash drop`.

### Result
Not yet run when this was written, so unverified. The history rewrite itself succeeded (no `co-authored` lines, new hashes); the force-push was still pending.

**Update (11:17):** Run by the user: merged 331 base + 4 earlier + 17 later lines into 352, then the stash was dropped. The force-push succeeded (`3a296d6...8fd15f2`).
