## 1. Add a legend for the agent trace log (20:03)

**Files:** `logs/logs_legend.md` (new)
**Context:** Follow-up to the agent tracing system (2026-10-08 entry 3). The user asked what `agent_events.jsonl` is
and wanted its terms written down.

### Before
Did not exist. The meaning of each event type and field in `logs/agent_events.jsonl` was only in the hook's source
code and in chat.

### Problem
The raw JSONL is hard to read without knowing the fields, e.g. what `span_id`, `error_sig` or `agent_result`
mean, or why a field is missing from some lines.

### Solution
Wrote a reference next to the log covering:
- the format and an example start/end line pair
- every event type
- the common, tool-call and outcome fields (taken from `agent_trace_hook.py`, so it also covers fields left out of
  the chat explanation, like `metrics`, `agent_result_error` and `payload_keys`)
- the `agent_result` keys for each subagent
- the redaction rules

### Result
The file was written and checked against the hook's field names. It's documentation only; no behaviour changed.
